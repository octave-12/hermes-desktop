# 更新日志

本文档记录 Hermes Desktop 项目的重要更新和变更。

## 2026-05-25 更新（微信集成重构）

### 重要变更

#### 从 iLink 轮询迁移到 Hermes Gateway

**重构背景**：
- 原方案使用 iLink API 轮询方式，稳定性差
- 新方案使用 Hermes 内置 Gateway（腾讯官方推荐的个人版）
- Gateway 作为独立进程运行，负责微信消息的接收、处理、回复

**删除的功能**：
- `backend/services/weixin_client.py` - iLink 客户端
- `backend/services/weixin_polling.py` - 轮询服务
- `backend/services/gateway_sync.py` - 同步服务

**新增的功能**：
- Gateway 状态查询 API
- Gateway 数据库浏览功能
- 微信会话置顶显示
- 微信图标和特殊样式

### 新增功能

#### 1. Gateway 微信集成

**核心特性**：
- 扫码登录微信个人号
- 消息自动同步到 Desktop
- 微信会话在会话列表中置顶显示
- 带微信图标的特殊样式

**技术实现**：
- Gateway 独立进程，端口 8766
- Desktop 直接读取 Gateway 的 state.db
- 使用单例模式，确保只有一个微信会话

**新增 API**：
- `GET /api/wechat/gateway/status` - Gateway 运行状态
- `GET /api/wechat/connections` - 微信连接列表
- `POST /api/wechat/gateway/start` - 启动 Gateway
- `POST /api/wechat/gateway/stop` - 停止 Gateway

#### 2. Gateway 数据库浏览

**功能特性**：
- 可视化查看 Gateway 的 state.db
- 只显示 sessions 和 messages 两个表
- 自动过滤空的工具调用消息
- 支持分页浏览

**新增 API**：
- `GET /api/gateway/tables` - 获取表列表（只返回 sessions 和 messages）
- `GET /api/gateway/tables/{table_name}` - 查看表数据

**过滤逻辑**：
- 过滤掉 `content` 为空的 assistant 消息
- 这些空消息是 Hermes Agent 的工具调用记录

#### 3. 数据库优化

**自动增量 VACUUM**：
- 启用 `PRAGMA auto_vacuum = INCREMENTAL`
- 启动时检查空闲页并回收
- 删除会话后触发 incremental_vacuum
- 压缩 hermes-desktop.db（373MB → 64KB）

**空闲页检查**：
- 使用 `PRAGMA freelist_count` 检查空闲页
- 空闲页超过 100 页时自动回收
- 日志输出回收结果

#### 4. 优雅停止

**停止脚本**：
- `stop.sh` - WSL 优雅停止脚本
- `stop.bat` - Windows 停止脚本
- `check-db.sh` - 数据库健康检查脚本

**停止策略**：
- 使用 `pkill -TERM` 而非 `pkill -9`
- 避免 SQLite WAL 数据库损坏
- 给进程 2 秒时间优雅关闭

**启动脚本优化**：
- `start.bat` 启动前先调用 `stop.sh`
- `debug-start.bat` 同样使用优雅停止
- 确保每次启动都是干净的环境

#### 5. 消息过滤优化

**过滤空白消息**：
- 过滤掉 `content` 为空的 assistant 消息
- 这些消息是工具调用的占位符
- 提高聊天界面的可读性

**实现位置**：
- `get_gateway_messages()` - 后端 SQL 过滤
- `/api/gateway/tables/messages` - 数据库浏览过滤

### 性能优化

#### 数据库性能

- 启用增量 VACUUM，防止数据库膨胀
- 定期回收空闲页，保持数据库紧凑
- 压缩后性能显著提升

#### 启动性能

- 优雅停止避免强制杀进程
- 数据库健康检查确保数据完整性
- 清理旧进程后再启动新服务

### 架构变更

#### 微信会话管理

- 微信会话使用单例模式
- 会话 ID 固定为 `wechat-singleton`
- 会话列表中只有一个微信聊天会话
- 微信会话置顶显示（SQL ORDER BY）

#### 数据流架构

```
微信消息 → Gateway → state.db → Desktop (只读)
                ↓
           Hermes Agent 处理
                ↓
           回复消息 → Gateway → 微信
```

## 2026-05-23 更新（多会话并发与数据库管理）

### 新增功能

#### 1. 多会话并发处理

**核心特性**：
- 支持最多 10 个会话同时生成回复，互不阻塞
- WebSocket 异步处理，心跳与 AI 生成完全独立
- 超出并发限制自动排队等待

**技术实现**：
- 使用 `asyncio.create_task()` 后台运行 chat 任务
- WebSocket 主循环不被 chat 阻塞，可实时响应心跳
- 每个会话独立消息队列，按顺序处理

#### 2. 消息队列管理

**功能特性**：
- 单会话消息队列可视化显示
- 支持查看队列项内容预览（前 50 字符）
- 支持删除单个队列项
- 实时更新队列状态

**新增事件**：
- `queue_updated` - 队列更新通知
- `session_waiting` - 会话等待并发槽位通知
- `remove_from_queue` - 删除队列项 API

#### 3. 应用主数据库管理

**功能特性**：
- 可视化管理 sessions、messages、config 表
- 支持查看、删除表数据
- 支持分页、排序、跳转
- SQL 白名单验证，防止注入攻击

**新增 API**：
- `GET /api/database/tables` - 获取表列表
- `GET /api/database/tables/{table_name}` - 查看表数据
- `DELETE /api/database/tables/{table_name}/{row_id}` - 删除表行

#### 4. 记忆管理增强

**新增内容**：
- 添加应用主数据库到记忆类型列表
- 支持记忆数据库和应用数据库分别管理

### 性能优化

#### 1. 超时设置优化

- API 模式超时：120秒 → 300秒（5 分钟）
- WebSocket 心跳超时：30秒 → 60秒
- 避免因 AI 生成阻塞导致频繁断开

#### 2. WebSocket 心跳优化

- 心跳与 AI 生成完全解耦
- 使用后台任务处理 chat，不阻塞主循环
- 心跳响应实时，不受 AI 生成影响

### 安全增强

- SQL 白名单验证（只允许 sessions、messages、config 表）
- 表名和主键使用字典映射，防止注入
- 分页参数验证（limit 1-1000）

### 问题修复

#### Git Bash 环境下的 nul 文件问题

**问题描述**：
- 项目根目录自动生成 `nul` 文件，删除后仍会再次出现

**原因分析**：
- Windows 中 `nul` 是保留设备名（类似 `/dev/null`）
- Git Bash 环境下运行包含 `>nul` 的 CMD 语法命令会创建实际的 `nul` 文件
- 正确做法：
  - Git Bash 使用 `>/dev/null`
  - CMD 使用 `>nul`

**解决方案**：
- 在 `.gitignore` 中添加 `nul` 文件忽略规则
- 提交：`a04c6c8: 将 nul 文件添加到 gitignore`

## 2026-05-16 更新

### 新增功能

#### 1. 静默启动功能

- 新增 `start.bat` 脚本实现一键静默启动
- 使用 VBScript 隐藏所有命令窗口
- 自动清理旧进程（node、electron、python）
- 只显示 Electron 客户端窗口，无任何命令窗口干扰

**工作流程**：
1. 清理所有旧进程
2. 隐藏启动后端服务（无窗口）
3. 隐藏启动前端应用（无窗口）
4. 启动窗口自动关闭

#### 2. 重启所有服务功能

- 在设置面板中新增"重启所有服务"按钮
- 一键重启前端和后端所有服务
- 自动清理进程并重新启动

**重启流程**：
- 客户端先清理所有进程
- 等待 3 秒释放资源
- 自动调用 `start.bat` 重新启动
- 新客户端窗口打开，旧窗口关闭
